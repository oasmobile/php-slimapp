# 普通进程测试无条件要求覆盖率驱动

## 观察到的行为

静态审查发现普通 UT 隐含依赖覆盖率扩展，审查优先级为 P2；尚未运行复现测试。

- `tests/ut/ForkProcessTest.php:30` 无条件向子进程传入 `COVERAGE_FILE`。
- 两个进程测试脚本据此调用 `Selector::forLineCoverage()`，未安装覆盖率驱动时会抛出异常。
- 成功场景会在业务代码之前失败；只检查退出码 255 的预期失败场景可能误通过。

## 期望行为

普通 UT 在具备项目要求的 PHP 和 pcntl 环境中可运行，覆盖率收集仅在显式请求时启用。
预期失败场景必须证明业务失败原因，不能只依赖可能被其它异常复用的退出码。

## 复现步骤

以下步骤作为后续复现测试的设计输入，尚未执行。

1. 准备 PHP 8.5、pcntl 和锁定的开发依赖，确保 PCOV 与 Xdebug 均未启用。
2. 通过普通 UT 入口运行 `ForkProcessTest`，不指定覆盖率参数。
3. 断言成功场景正常退出，记录当前脚本实际抛出的覆盖率驱动异常。
4. 检查预期失败场景是否执行了目标业务分支，排除初始化异常造成的假通过。

## 影响

未启用覆盖率扩展的开发机和 CI 会发生测试失败或误判，不直接影响生产业务运行。
当前审查环境启用了 PCOV，因此不能以当前环境能运行测试排除此缺陷。

## 所需回归证据

回归必须覆盖普通执行与显式覆盖率执行两个模式。

- 修复前：无覆盖率驱动时，成功场景因驱动异常而失败。
- 修复后：无驱动的普通测试通过，失败场景能证明预期业务原因。
- 显式覆盖率模式：有驱动时仍生成可读取的报告；缺少驱动时给出明确失败原因。
