# 文档结构规则

本规则适用于 MDF 生成或管理的全部 Markdown，修复方向是结构化，不是压缩措辞或删减信息。

- PRP 与交付总结的 HTML 可见正文同样遵循写作原则与内容形态；格式见 [HTML 工作材料](html-materials.md)。

- 目标仓库：根文档、`docs/**`、`changes/**` 与 `AGENTS.md` 托管区块。
  - `docs/JOTS.md` 免结构限制；MDF 新写或改写的说明性文本仍采用下方写作原则。
- MDF 自身：Skill、intent、模板、`docs/` 与根文档。
- 目标项目中命中 `.mdf/modules.yaml` module `ignore` 的文件，免除本文结构硬限制与超限拆分要求。
  - 沿用现有 `pattern` + `reason`，不另加配置；审阅报告排除依据，不再要求这些文件拆分。

## ASD-STE100 写作

文档格式与表达尽量遵循 [ASD-STE100](https://www.asd-ste100.org/STE_faq.html) 的技术写作原则。

- 该标准针对 English；简体中文采用可适用的原则，不套用 English 词典与字数限制。
- 新建或改写说明性文本时采用下表原则；保留项目要求的语言和软件工程术语原文。

| 方面 | 写作原则 |
| --- | --- |
| 句子 | 使用短句；一句表达一条规则、一个事实或一个主要操作。 |
| 动作 | 优先使用主动语态与具体动词；明确主体、动作和对象，避免模糊指代。 |
| 术语 | 同一概念使用同一术语；必要时在 `GLOSSARY.md` 定义，避免同义词混用。 |
| 步骤 | 先写操作前必须知道的条件；每步一个主要操作，必要时说明预期结果。 |
| 保真 | 保留规则强度、条件、例外、数值和证据；简化表达不得改变技术含义。 |

- 写入后人工复核这些原则；原始引用、日志、代码与项目要求的固定文案保持原样。
- 本约定不代表 ASD-STE100 符合性声明；CLI 的 `prose.*` 检查只验证下方结构硬限制。

## 结构限制与内容形态

**机械限制**：硬限制由 CLI `fact-audit` 报 `prose.*` finding。
只设硬限制，不得当作可忽略建议；字符按显示宽度计，中文及其他全角、宽字符算 2 个。

| code | 度量 | 硬限制 | 超限后每个拆分结果上限 |
| --- | --- | --- | --- |
| `prose.block` | 连续散文物理行（不含列表、表格、代码、标题） | 6 | 4 |
| `prose.sentence` | 单句显示宽度（按句末标点切分，链接只计文字） | 200 | 140 |
| `prose.list_item` | 单个列表项含续行的物理行 | 4 | 2 |
| `prose.section` | 一个标题下的散文行合计 | 15 | 10 |
| `prose.emoji` | 允许集合外的 emoji | 0 | 移除违规 emoji |

- 文档拆分先梳理信息结构，按文档角色、主题、读者与任务确定页面边界。
  - 每页回答一个完整主题或任务，保留上下文及必要链接；路由页只导航，主题叶保持唯一归属。
  - 可按信息结构调整主题页入口与导航，并同步更新链接；不强求在原主题页保留转发壳。
  - 标题与文件名表达主题，不得按行数机械切成 `part1`、`part2`；仅改名不能替代结构拆分。
  - 审阅须核对各页主题、读者、导航与完整性；仅行数达标不能通过。
- 超限必须拆分，每个结果不得超过对应硬限制的 70%，整数向下取整。
  - 70% 是拆分后的验收上限，不是切割位置。
- 跨物理行的同一句仍合并计数；单句超限必须拆句，不能只换行。
- CLI 检查当前硬限制；审查按改写前内容复核拆分结果，不得仅压到硬限制以下。

**内容形态**（必须按表组织，不是建议）：

| 内容 | 必须写成 |
| --- | --- |
| 并列 3 项以上 | 列表 |
| 两个以上条件分支 | 表格或决策树 |
| 3 步以上有序流程 | 编号列表或图 |
| 多个对象 × 多个属性 | 表格 |
| 规则带例外或细节 | 主规则一级列表，例外与细节放二级 |

- 每节开头必须用一句话说明本节解决什么。
- emoji 只用 ⚠️ 易错与警告、✅ 允许、❌ 禁止、💡 提示、📌 关键约束、
  📂 工作区目录、📍 当前分支、⬇️ 工作区切换。
  - 只作行首标记，可跟在列表符号之后。
  - ⬇️ 只作为切换横幅的中间一行，不作文内标记。
  - ❌ 不用在标题、表头与代码中，不作装饰。
