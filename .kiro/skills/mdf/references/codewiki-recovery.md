# CodeWiki Recovery

由 CodeWiki 生成、更新流程在失败或需要重建时读取；不构成新的公开 intent。
调用方提供 `REPO_ROOT`、session ID、实际 workspace、写入记录、失败步骤、失败原因（含是否需要重建或删页）
与 diff。
步骤 2 与 3 互斥，均由步骤 1 进入，不是彼此的后续；框序受编号约束仍为 1–5。
仅处理 MCP 失败、输出验收失败或必要重建；输出已验收且仅 Git 暂存或提交失败，
由调用方保留产物并处理提交，不进入本流程。

## 决策树

```text
┌──────────────────────────────────┐
│ 1 Classify recovery              │
└────────────────┬─────────────────┘
                 │
                 ├──── 缺调用方上下文 ────────→ [报告缺项并停止]
                 ├──── 已写页面或无法确定 ────→ 3 Preserve session
                 │
                 ▼ 未写页面（含无会话或需要重建）
┌──────────────────────────────────┐
│ 2 Close unwritten session        │
└────────────────┬─────────────────┘
                 │
                 ├──── 无残余且无需重建 ────────────→ [报告失败，停止]
                 └──── 需要重建、残余或关闭失败 ────→ 4 Confirm backup

步骤 3 仅由步骤 1「已写页面或无法确定」进入，不是步骤 2 的后续。

┌──────────────────────────────────┐
│ 3 Preserve session               │
└────────────────┬─────────────────┘
                 │
                 ├──── 同会话可修复 ────→ [返回调用方失败步骤]
                 ├──── 用户暂停 ────────→ [保留现场，停止]
                 └──── 无法续办 ────────→ 4 Confirm backup

步骤 4 由步骤 2 需要重建、残余或关闭失败，或步骤 3 无法续办进入，不是步骤 3 的后续。

┌──────────────────────────────────┐
│ 4 Confirm backup                 │
└────────────────┬─────────────────┘
                 │
                 ├──── 未确认或路径无效 ────→ [保留现场，停止]
                 │
                 ▼ 用户明确确认
┌──────────────────────────────────┐
│ 5 Move and hand off              │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败 ────→ [报告实际位置，停止]
                 └──── 成功 ────→ [提交备份改动后显式 codewiki generate]
```

## 工作流（唯一执行契约）

| # | 步骤 | 类型 | 做什么 | 证据 | 通过 → | 失败/缺失 → |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Classify recovery | 约束 | 按优先级判定写入状态 | 文件与写入记录 | 未写→2；已写或无法确定→3 | 缺调用方上下文则停 |
| 2 | Close unwritten session | 脚本 | 关闭可用会话并核对残余 | diff、残余 | 无需重建报告失败；需重建 4 | 残余或失败 4 |
| 3 | Preserve session | 约束 | 保留已写会话并记续办条件 | 失败步骤、路径 | 返回失败步骤 | 暂停则停；无法续办 4 |
| 4 | Confirm backup | 约束 | 核对仓外备份源和目标，取得具体搬移确认 | 路径、用户明确确认 | 5 | 保留现场，停止 |
| 5 | Move and hand off | 约束 | 按确认方案搬移核对后交接重建 | 备份、diff、原位状态 | 交接后结束 | 报告实际位置，停止 |

## 术语与数据结构

### 会话状态

<a id="state"></a>

先读取 MCP 结果和实际文件；区分未成功写页面、已成功写入或编辑页面、会话已关闭或
不可恢复。步骤 1 按以下优先级判定：

1. 已写页面或不能确认是否写过：按已写处理，进入 3。
2. 其余情况均为未写页面，进入 2；是否需要重建（含会话不可恢复）只决定 2 成功后的去向。

不依靠等待 session 过期来清理，不使用未经工具支持的 abort 或跳过 metadata 参数。

<a id="unwritten"></a>

确认未成功写入或编辑页面后，会话仍可用时先调用 `close_session` 清理；无 session
（未创建或已关闭）时不调用关闭，只做下述核对。
随后检查当前 workspace 确已清理、Wiki diff 无变化；`analyze_repo` 或
`save_module_tree` 的额外产物也必须检查。

- 无残余且无需重建：报告原业务流程失败并停止。
- 需要重建：关闭并核对后进入 4，不留下未关闭会话或 workspace。
- 有残余或关闭失败：保留现场并进入 4 准备备份方案。
- ❌ 任何情况都不得报告原业务流程成功。

<a id="partial"></a>

已部分写入时不调用 `close_session`，不开始另一次增量更新，不推进基线；记录失败
步骤、页面、session ID 与实际 workspace。同一会话可恢复时只返回原失败步骤修复，
调用方在全部页面、链接和事实验收成功后才关闭会话。用户暂停时保留现场并明确列出
续办条件；会话已失效、关闭后验收失败或无法修复时准备备份重建。

### 备份与重建

<a id="backup"></a>

列出 `docs/repowiki/` 和本次 session workspace 的实际路径、变更清单，以及用户指定的
仓外备份位置。明确说明将搬移整个旧 Wiki，不能把它当作新的增量基线；保留代码优先的
只读 reference 用途。目标须在仓外、不存在且可写，不得覆盖内容，不跟随符号链接，
不包含源目录；不得涉及其他 session 或业务文件。取得针对具体源和目标的明确确认。
尚可用但已有写入的 session 保持不关闭；搬移后不得再调用该 session 的写入或关闭工具。

<a id="move"></a>

仅按确认方案用文件搬移保留旧 Wiki 和本次 workspace，逐项核对文件清单与内容一致，
以及源目录已移出；空的本次 `.codewiki/` 容器只可随备份移出，不触及其他会话内容。
这是整体备份的例外，不允许直接编辑页面或 metadata，也不删除 `.mdf/`、`docs/` 产出物。
搬移失败时列出每项实际位置并停止，不自动覆盖、回退或继续生成。

成功后展示备份位置与仓库 diff，复核并提交目录移出改动；后续由用户显式
`$mdf codewiki generate`。新调用只由 MCP 生成新基线；不重新路由回 update。
