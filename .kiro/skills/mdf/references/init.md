# Init

它按项目状态分流：新项目内部执行 bootstrap，已有项目或配置调整内部执行
migrate。migrate 是 init 的子 intent：`$mdf init migrate`；也可 `$mdf migrate`。
bootstrap 仍可直接调用。

## 选择树

```text
┌──────────────────────────────────┐
│ 1 Check entry                    │
└────────────────┬─────────────────┘
                 │
                 ├──── 边界不明 ────→ [澄清后返回 1]
                 ├──── 其他异常 ────→ [停止并报告]
                 │
                 ▼ 判定完成
┌──────────────────────────────────┐
│ 2 Dispatch                       │
└────────────────┬─────────────────┘
                 │
                 ├──── 已有事实或已 ready ──────────→ [内部执行 migrate 并返回]
                 ├──── MDF 内容不符合当前契约 ──────→ [内部执行 migrate 并返回]
                 ├──── 未就绪、无事实且符合契约 ────→ [内部执行 bootstrap 并返回]
                 └──── 失败/缺失 ───────────────────→ [停止并报告]
```

## 工作流（唯一执行契约）

表中操作与证据按下方同名条目核对；顺序与跳转只由本表规定。

完整读取 `references/initialization.md`、`references/common.md`
与 `references/repository-contract.md`。步骤 2 按判定读取并内部执行
`references/bootstrap.md` 或 `references/migrate.md`。

| # | 步骤 | 类型 | 做什么 | 证据 | 通过 → | 失败/缺失 → |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Check entry | 约束 | 只读判定分流 | 边界、事实、MDF 状态 | 2 | 不明回 1；其他停止 |
| 2 | Dispatch | 约束 | 内部执行 bootstrap 或 migrate | 委托结果 | 按选择树结束 | 停止 |

## 术语与数据结构

### 入口与分流

<a id="s1"></a>

**入口**

先按 `initialization.md` 只读确认项目边界、新旧与 MDF 状态。转入前不写入 `.git/`，
不要求用户重新调用。不因普通目录、无提交或 dirty 一概拒绝。

可选加速（见 `common.md`「Jev 可选加速」）：

- 仅当只读证据对 bootstrap / migrate **语义仍歧义**且 tool 可用时。
- 调用：`choice`；state = 边界摘要与 MDF/事实迹象。
- 选项：`bootstrap` / `migrate` / `ask`。
- CLI 或 initialization 已明确时 ❌ 不调。
- 采信后落入步骤 2 同一分支；`ask` 或未采信走主 Agent / 澄清。

验收：明确项目根、判定依据。

异常与交接：边界或改动归属不明时澄清，其他异常报告后停止。中间反馈继续本次
流程，不重查入口。

### 分流

<a id="s2"></a>

**分流**

未就绪、没有事实且符合当前契约时，说明依据后内部执行 bootstrap 并返回其结果。
已有实际实现或运行事实、已 ready，或 MDF 内容不符合当前契约时，内部执行 migrate 并返回其结果。
复用已确认信息，不重复提问。被委托流程按其契约准备 Git、落地、审阅或核对
并确认启用。

验收：命中且执行了唯一被委托流程。

异常与交接：被委托流程失败或缺失时保留其现场并停止；不改走另一分支。
