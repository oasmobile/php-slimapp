# Bug Create

## 决策树

```text
┌──────────────────────────────────┐
│ 1 Check entry                    │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [停止]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 2 Resolve bug                    │
└────────────────┬─────────────────┘
                 │
                 ├──── open/fixed/rejected ────→ [停止并交接]
                 ├──── 需澄清或消歧 ───────────→ 2 Resolve bug
                 │
                 ▼ 输入唯一且完整
┌──────────────────────────────────┐
│ 3 Clarify                        │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [不写对象，停止]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 4 Confirm                        │
└────────────────┬─────────────────┘
                 │
                 ├──── 取消或拒绝 ────────────→ [停止]
                 ├──── 输入对象或来源变化 ────→ 2 Resolve bug
                 ├──── 既定对象需澄清 ────────→ 3 Clarify
                 ├──── 未确认且内容未变 ──────→ 4 Confirm
                 │
                 ▼ 用户确认 open
┌──────────────────────────────────┐
│ 5 Create bug                     │
└────────────────┬─────────────────┘
                 │
                 ├──── 失败/缺失 ────→ [保留现场，停止]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 6 Report                         │
└────────────────┬─────────────────┘
                 │
                 ├──── 通过 ─────────→ [结束]
                 └──── 失败/缺失 ────→ [停止]
```

## 工作流（唯一执行契约）

表中操作与证据按下方同名条目核对；顺序与跳转只由本表规定。

完整读取 `references/common.md`、`references/repository-contract.md` 与
`references/object-contract.md`。
步骤 3 读取并内部执行 `references/clarify.md`。

| # | 步骤 | 类型 | 做什么 | 证据 | 通过 → | 失败/缺失 → |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Check entry | 脚本 | 运行 `doctor`，核对已初始化 | doctor 结构化结果 | 2 | 未就绪则停 |
| 2 | Resolve bug | 脚本 | 用 `list` 查重并确认单个 Bug | list 结果、唯一对象 | 3 | 非 closed 命中则停；否则留 2 |
| 3 | Clarify | 约束 | 内部 clarify 补齐行为、复现、影响及必填字段 | 完整必填事实 | 4 | 不写对象，停止 |
| 4 | Confirm | 约束 | 展示边界和排除范围，取得明确 open 确认 | 用户确认 | 5 | 未确认留 4；取消停；来源变 2；事实变 3 |
| 5 | Create bug | 脚本 | 确认 slug，生成 ID、写 open、校验并回读 | 零 finding、对象与 diff | 6 | 保留现场，停止 |
| 6 | Report | 约束 | 报告 open Bug、确认事实和排除范围 | 结果摘要 | 结束 | 停止 |

## 术语与数据结构

### 入口与输入

<a id="s1"></a>

**入口**

解析 `REPO_ROOT` 并运行 `doctor`。
核对 `is_git_root: true`、`initialized: true`、`state: ready`。

- 不将 `normal_workflows_allowed: true` 作为前置条件。
- 活干到一半时文档 stale 是正常的；`evidence.stale` 等 findings 报告后继续。

验收：仓库已初始化且 manifest ready。

异常与交接：未初始化或 manifest 未就绪时提示 `$mdf init` 并停止。

<a id="s2"></a>

**对象**

- 接收用户手动提供的单个 Bug 事实；一次不得创建多个对象。
- 运行 `list --repo "$REPO_ROOT" --type bug --status open --status fixed --status rejected --status closed`。
  以用户输入的标题与正文对照输出中的 `title` 查重；不读取既有对象正文。
  - `open` / `fixed` / `rejected`：不新建，提示在既有对象中补充。
  - `closed`：继续新建，正文写明回归自该旧 Bug 的完整 ID。
  - 不逐篇翻阅 `docs/bugs/`。
- 外部想法、 当前聊天上下文或外部文档必须显式调用 `$mdf intake`。

验收：确认的 Bug 与采用范围。

异常与交接：`open` / `fixed` / `rejected` 停止并交接；`closed` 继续；范围不明时留在 2。

### 事实与确认

<a id="s3"></a>

**澄清**

使用内部 clarify intent 澄清观察到的行为、期望行为、复现步骤、影响、 所需回归证据、`found_in`
与 severity。

验收：完整必填事实。

异常与交接：必填事实仍无法确认时停止，不得写入任何对象。

<a id="s4"></a>

**确认**

展示 Bug、边界和排除范围。

验收：只有用户明确确认 open 才继续。

异常与交接：取消或拒绝则停止；输入对象或来源变化时回到 2；既定对象的事实、范围或验收需澄清时回到 3。
未取得明确确认且内容未变时留在 4 等待，不把未答复视为事实变化。
来源变化与事实变化同时成立时，优先回到 2。

### 对象写入与交接

<a id="s5"></a>

**创建**

- 为 Bug 提议并确认英文 ASCII kebab-case slug。
  - 须在 active Proposal 与 Bug 中唯一，且不得与对象 ID 同形。
- 使用 `make-id --type bug --repo "$REPO_ROOT" --slug <slug>` 生成 ID 与规范化文件名。
  再以模板写入 `docs/bugs/`，状态为 `open`。
- 写入后运行 `validate --repo "$REPO_ROOT" --level basic`。
  - 回读对象并对照模板、确认事实与完整 diff。
  - 核对 schema、必填章节及 `open` 状态。

验收：open Bug、校验退出 0 且零 finding、回读结果与 diff。

异常与交接：校验、回读或核对失败时：

- 停止并保留现场，报告 findings 与实际已写对象。
- ❌ 不得宣称创建验收通过，不进入步骤 6 的成功报告。

<a id="s6"></a>

**报告**

展示 open Bug、确认事实和排除范围。

验收：会话摘要。

异常与交接：停止。
