# Prettify

## 决策树

```text
┌──────────────────────────────────┐
│ 1 Resolve scope                  │
└────────────────┬─────────────────┘
                 │
                 ├──── 清单为空 ────────────────→ [报告并结束]
                 ├──── 参数冲突或缺路径 ────────→ [停止并询问]
                 ├──── 路径不允许或其他失败 ────→ [停止并报告]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 2 Check                          │
└────────────────┬─────────────────┘
                 │
                 ├──── 无待改写文档 ──────────→ [报告并结束]
                 ├──── 输出缺失或不可解析 ────→ [停止并报告]
                 │
                 ▼ 有待改写文档
┌──────────────────────────────────┐
│ 3 Rewrite                        │
└────────────────┬─────────────────┘
                 │
                 ├──── 语义不明 ────→ [停止并询问]
                 │
                 ▼ 已改写
┌──────────────────────────────────┐
│ 4 Verify                         │
└────────────────┬─────────────────┘
                 │
                 ├──── 未通过且改写不足两次 ────→ 3 Rewrite
                 ├──── 未通过且已改写两次 ──────→ [停止并报告]
                 ├──── 输出缺失或不可解析 ──────→ [停止并报告]
                 │
                 ▼ 通过
┌──────────────────────────────────┐
│ 5 Record                         │
└────────────────┬─────────────────┘
                 │
                 ├──── 通过 ─────────→ [结束]
                 └──── 失败/缺失 ────→ [停止并报告]
```

## 工作流（唯一执行契约）

读取 `references/common.md` 与 `references/doc-structure.md`。

| # | 步骤 | 类型 | 做什么 | 证据 | 通过 → | 失败/缺失 → |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Resolve scope | 约束 | 解析参数与文档清单 | 分支、文档清单 | 有清单则 2；空则结束 | 冲突则询问；否则停 |
| 2 | Check | 脚本 | 记基线并运行 prose-check | 基线、违例、审阅发现 | 有待改写 3；否则报告结束 | 输出失败则停止报告 |
| 3 | Rewrite | 约束 | 逐份结构化改写，不改语义 | 改写后的文档、改写次数 | 4 | 语义不明则停止询问 |
| 4 | Verify | 脚本 | 复跑两项检查并对照语义 | 零违例、不新增 finding、语义对照 | 5 | 未过且不足两次回 3；否则停止报告 |
| 5 | Record | 约束 | 提交本次改写并报告 | 提交、改写清单 | 结束 | 停止并报告 |

`$mdf prettify [<path>...] [--scope branch|full|paths]` 执行本流程。

## 术语与数据结构

### 范围与分支

本节确定改哪些文档、在哪个分支上改。

| 调用 | 待美化文档 |
| --- | --- |
| `--scope full` | 全部带角色的 Markdown（`docs/JOTS.md` 除外） |
| `--scope branch`（默认） | 当前分支相对起点改动过的带角色文档 |
| `<path>...` 或 `--scope paths <path>...` | 所列仓库内 Markdown 文件 |

- 参数解析：
  - 给出 `<path>...` 即 `--scope paths`。
  - ❌ `<path>...` 与 `--scope full` 或 `--scope branch` 同用时停止询问。
  - ❌ `--scope paths` 未列路径时停止询问。
- `--scope branch` 的起点同 `fact-audit.md` 的 branch 规则：
  - release 取上一正式发布的 commit/tag；首次发布无上一版本时停止确认初始基线。
  - 其他交付分支取 `delivery.json` 的 `start_commit`。
  - 没有时取 git config `branch.<owner 分支>.mdf-start-commit`，再没有则取 `git merge-base develop HEAD`。
  - 取不到起点时停止并报告。
  - 用 `git diff --name-only <base>`（含未提交改动）与 `git ls-files --others --exclude-standard` 列出改动。
  - 从中筛出仍存在、带角色且不在下方「不改」之列的 Markdown，逐个作为 `--path`。
  - 清单为空时报告「无待美化文档」并结束，不调用 `prose-check`。
- 步骤 1 拒绝不允许的路径：`docs/JOTS.md`、`docs/repowiki/**`、非 Markdown 或仓库外路径。
  - 显式列出这类路径时停止并报告，不静默跳过。
  - full 与 branch 自动清单只选 Markdown；ready PRP 的 HTML 不进入本 intent。
- 命中 `.mdf/modules.yaml` module `ignore` 的文件从待美化清单排除，显式指定路径时同样排除。
  - 报告匹配 pattern 与 reason；排除后清单为空则报告并结束，不强制改写。
- 写入分支遵守 `common.md` 的写入规则。
  - ❌ 不在 master 上直接改写。
  - 与当前交付相关的文档在该交付分支改写；其余在 develop 或 planning 按公共规则处理。
- ✅ 可改：根文档（`AGENTS.md` 仅托管区块外）、`docs/**`。
- ❌ 不改：`docs/JOTS.md`、`docs/repowiki/`、`AGENTS.md` MDF 托管区块、代码块内容、frontmatter 键、
  `{{MDF_...}}` 槽位。
  - 托管区块由 upgrade 按上游模板覆盖；其违例记为模板问题并在报告中列出，不进入改写。

### 检查与改写

先记录 validate 基线，再用 CLI 列出硬限制违例，最后按审阅规则找出需要结构化的段落。

- 运行 `python3 "$MDF_ROOT/scripts/mdf.py" validate --repo "$REPO_ROOT"`，记录基线 finding code。
- 运行 `python3 "$MDF_ROOT/scripts/mdf.py" prose-check --repo "$REPO_ROOT"`。
  - 所有 scope 都按步骤 1 的 Markdown 清单逐个附加 `--path`，不使用 CLI 默认全库范围。
  - 清单为空时不调用，禁止退化成全库检查。
- ⚠️ 两个命令有 finding 或违例时退出码为 2：
  - 退出码 2 且输出可解析的 JSON payload，表示有 finding 或违例，按 payload 继续。
  - 仅退出码 0 或 2 且对应命令的结构化结果完整时继续。
  - 退出 2 且仅因 findings/违例而 `ok:false` 仍按检查结果处理，不单独视为工具错误。
  - 其他退出码、含 `error` 而无检查结果的错误 envelope、缺预期字段、无输出或不可解析均失败。
- 必须按 `doc-structure.md` 的硬限制、超限后的 70% 拆分要求与内容形态改写，不得当作可选审阅。
- 同时按 `doc-structure.md` 的 ASD-STE100 写作约定简化表达并人工复核，保持下方语义不变。
- 违例全部属于 `AGENTS.md` 托管区块且审阅无发现时，无待改写文档，报告模板问题后结束。
- 必须按原文形态改写为对应结构，不得保留大段散文：

| 原文形态 | 必须改写为 |
| --- | --- |
| 大段说明 | 一句概述加列表 |
| 并列多项 | 列表或多级列表 |
| 条件分支 | 表格或决策树 |
| 有序流程 | 编号列表或图 |
| 对象与属性 | 表格 |
| 易错点、禁止项 | ⚠️、❌ 行首标记 |

- 📌 只改结构，不改语义：
  - 每条规则、条件、例外、数值、路径、命令与链接都要保留。
  - 不新增事实，不改变措辞的强度（必须、可以、不得）。
  - 标题与 `<a id>` 锚点保持可被原有链接命中。
- 语义有歧义、改写须取舍内容时停止询问，不自行裁定。

### 复核与记录

改写后用确定性检查与逐份对照两层确认；步骤 3 最多执行两次。

- 复跑 `prose-check`，范围内除 `AGENTS.md` 托管区块外零违例；退出码 2 按上方规则解析。
- 复跑 `validate --repo "$REPO_ROOT"`，与步骤 2 基线相比不新增 finding code；
  退出码 2 且可解析时按 payload 比较。
- 逐份对照改写前后的 diff，列出每条原有规则在新文本中的位置；缺失即语义丢失。
- 仍有违例、新增 finding 或语义丢失即未通过：
  - 改写不足两次时回步骤 3。
  - 已改写两次时停止并报告剩余违例、新增 finding 与缺失规则。
- 提交使用中文 Conventional Commit，只含本次改写的文档。
- 报告改写文档清单、每份的主要结构变化、复核结果与模板问题。
